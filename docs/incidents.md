# Проверочные инциденты

Все сценарии воспроизводятся на поднятом `docker compose up`. Для каждого описано:
как воспроизвести, что видит пользователь, что попадает в логи/метрики, как происходит
восстановление. Сценарии №2, №4 (механизм) и №6 проверены при разработке вживую.

## 1. Пустой или неизвестный жанр в данных

**Воспроизведение:** в `data/demo/games.csv` игры с пустыми тегами отфильтровываются ещё
на этапе подготовки demo-набора (`ml/make_demo.py` берёт только игры с тегами); незнакомый
тег в предпочтениях пользователя — легальный ввод:

```bash
curl -X POST http://localhost:8000/users/<id>/preferences \
  -H "Content-Type: application/json" \
  -d '{"genres":["НесуществующийЖанр"],"max_price":25,"blocked_tags":["ТожеНет"]}'
```

**Что видит пользователь:** выдача работает — несоответствующий жанр просто не даёт
буста, несуществующий стоп-тег ничего не блокирует (сравнение множеств, регистронезависимое).
Пустой список стоп-тегов отклоняется валидацией (422 с понятной ошибкой) — это покрыто
интеграционным тестом.

**Логи/метрики:** обычный запрос в логе с user id и моделью; ошибок нет.

**Восстановление:** не требуется — деградации нет по построению.

## 2. Файл модели удалён, повреждён или несовместим

**Воспроизведение:**

```bash
mv ml/artifacts/hybrid_current.json ml/artifacts/hybrid_current.json.bak
# или echo "{broken" > ml/artifacts/hybrid_current.json
curl http://localhost:8000/users/<id>/recommendations
```

**Что видит пользователь:** топ-10 приходит как обычно, но в ответе честно указано
`"model_name": "baseline", "model_version": "v1"` — сработал fallback на популярностную
модель с теми же фильтрами бюджета и стоп-тегов.

**Логи/метрики:** `WARNING fallback на baseline: артефакт гибридной модели недоступен...`;
в `/metrics` растёт счётчик `served_by["baseline v1"]` — распределение fallback видно живьём.

**Восстановление:** вернуть файл (`mv` обратно) — следующий же запрос обслуживается
гибридом без рестарта (кэш перечитывает артефакт по mtime и сверяет версию с активной
ModelVersion). Несовместимость версий (артефакт от другой версии) ловится той же сверкой
и также уводит в fallback.

## 3. Один и тот же interaction отправлен повторно

**Воспроизведение:**

```bash
curl -X POST http://localhost:8000/users/<id>/interactions \
  -H "Content-Type: application/json" -d '{"game_id":730,"kind":"like"}'
# повторить ту же команду
```

**Что видит пользователь:** оба запроса успешны, второй возвращает `"duplicate": true`;
в интерфейсе кнопки фидбека блокируются после первого нажатия.

**Логи/метрики:** обычные записи; дубликата в БД нет — уникальный констрейнт
`(user_id, game_id, kind)` + `ON CONFLICT DO NOTHING`.

**Восстановление:** не требуется; идемпотентность покрыта интеграционным тестом.

## 4. Модель отвечает слишком долго или падает

**Воспроизведение (управляемая задержка скоринга):**

```bash
# в docker-compose.yml сервису backend добавить в environment:
#   MODEL_DELAY_SECONDS: "5"
docker compose up -d backend
curl http://localhost:8000/users/<id>/recommendations
```

**Что видит пользователь:** ответ приходит примерно за таймаут (2 с,
`MODEL_TIMEOUT_SECONDS`) — выдача baseline с честной пометкой модели, не зависший запрос.

**Логи/метрики:** `WARNING fallback на baseline: TimeoutError`; latency и распределение
`served_by` в `/metrics`.

**Восстановление:** убрать переменную и перезапустить backend. Известное ограничение
задокументировано в коде: поток скоринга дорабатывает вхолостую (asyncio.to_thread
не прерывается), при постоянных таймаутах пул потоков — узкое место.

## 5. Пользователь без истории и игра без отзывов

**Воспроизведение:** создать пользователя, задать только предпочтения (без лайков)
и запросить рекомендации.

**Что видит пользователь:** осмысленный топ-10 — у гибрида при пустой истории similarity
нулевая, работает популярностный член с фильтрами по бюджету/стоп-тегам и объяснением
«Популярная игра: …» (cold start по построению формулы). Игры без отзывов в train не
попадают в соседей item-item и не рекомендуются коллаборативным сигналом — путь для них
content-based/популярность внутри жанра (см. «Ограничения» в README).

**Логи/метрики:** обычный запрос; в разрезах evaluation видно, что качество растёт
с историей (P@10 0.0083 при 1–2 лайках → 0.0211 при 3+).

**Восстановление:** не требуется — сценарий штатный.

## 6. Новая модель хуже baseline

**Воспроизведение:**

```bash
curl -X POST "http://localhost:8000/admin/retrain?simulate_degraded=true"
curl http://localhost:8000/admin/jobs/<job_id>
```

**Что видит пользователь:** ничего — выдача продолжает идти прежней версией.
Ответ джобы: `{"status":"rejected","gate_precision_at_10":0.0,"baseline_p10":0.0075}`.

**Логи/метрики (worker):** `WARNING promotion gate: vN отклонена (P@10 0.0000 <= baseline
0.0075) — активная не меняется`; отклонённая версия сохраняется в таблице `model_versions`
с `is_active=false` и метриками gate — аудит-след виден в БД, активная версия — в
`/admin/models/current`.

**Восстановление:** автоматическое по построению — promotion gate не активирует модель,
не побившую baseline; артефакт на диске не перезаписывается. Обычный
`POST /admin/retrain` после исправления данных обучает и активирует здоровую версию
(проверено: v5 promoted с gate P@10 0.021).
